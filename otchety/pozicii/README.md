# Дашборд позиций — как добавить новую неделю

Адрес страницы: **https://amithaver.github.io/avant-reports/otchety/pozicii/**
Он постоянный. Клиенту выдаётся один раз и больше не меняется — сколько бы
недель ни прошло. Короткая ссылка `/pozicii/` ведёт сюда же.

---

## Три шага

**1. Выгрузить свежий срез из Serpstat** в тот же вид, что и прошлые:
`serpstat_позиции_<ГГГГ-ММ-ДД>.json`. Класть рядом с остальными, в
`G:\Мой диск\MESHKOR — Клиенты\AVANT\20_САЙТ_И_SEO\25_ДАННЫЕ\`.

**2. Прогнать конвертер** — из корня репозитория, одной строкой:

```
python tools/serpstat_to_dashboard.py "G:\Мой диск\MESHKOR — Клиенты\AVANT\20_САЙТ_И_SEO\25_ДАННЫЕ\serpstat_позиции_2026-09-02.json"
```

Он сам положит `data/2026-09-02.json`, обновит словарь фраз и допишет строку
в `data/index.json`. Прошлые недели не трогает.

**3. Проверить и выложить.**

```
node tools/check_dashboard.mjs
```

Проверка должна закончиться строкой «Все проверки пройдены». После этого —
обычный `git add` / `commit` / `push`.

**Вёрстку править не нужно ни в одном из шагов.** Если для новой недели
понадобилось открыть `index.html` — что-то пошло не так, так быть не должно.

---

## Посмотреть локально до выкладки

Браузер не даёт странице читать соседние файлы с диска напрямую, поэтому
двойным щелчком по `index.html` дашборд не откроется. Нужен локальный сервер —
из корня репозитория:

```
python -m http.server 8781
```

и открыть `http://localhost:8781/otchety/pozicii/`.

## Что где лежит

```
otchety/pozicii/
  index.html     каркас страницы. Цифр внутри нет вообще
  app.css        оформление, светлая и тёмная тема
  app.js         все расчёты. Считает в браузере при открытии
  data/
    index.json   манифест: перечень срезов
    keywords.json словарь фраз и разметки, общий для всех недель
    2026-08-09.json … позиции за неделю, только числа
tools/
  serpstat_to_dashboard.py   конвертер выгрузки в data/
  check_dashboard.mjs        проверка расчётов на настоящих данных
```

---

## Формат данных

Колоночный: значения лежат параллельными массивами, порядок один и тот же во
всех файлах. Так текст фразы хранится один раз, а не повторяется в каждой
неделе — весь набор из пяти недель весит 190 КБ вместо нескольких мегабайт.

**`keywords.json`** — то, что не меняется от недели к неделе:

| поле | что это |
|---|---|
| `ids` | `keyword_id` из Serpstat, по порядку |
| `kw` | текст фразы |
| `lang`, `type`, `theme` | язык, тип запроса, направление — как `{dict, idx}`: `dict[idx[i]]` даёт значение для фразы `i` |
| `local` | 1, если в запросе есть название города |
| `vol` | частотность |

**`data/<дата>.json`** — то, что меняется:

| поле | что это |
|---|---|
| `pos` | позиция фразы, по тому же порядку. `null` = фразы нет в первой сотне |
| `url` | посадочная страница на этом замере, как `{dict, idx}` |
| `ranked` | сколько фраз попало в сотню — для быстрой проверки |

**`data/index.json`** — манифест. Одна строка на срез:
`{"date", "file", "label", "partial"}`. `partial: true` помечает неполный
съём: такой срез остаётся выбираемым, но на график не идёт и предупреждает о
себе плашкой.

Ничего предпосчитанного в файлах нет намеренно. Все суммы, средние, дельты и
сравнения считаются в браузере на лету — иначе выбор произвольной пары недель
для сравнения был бы невозможен.

---

## Три вещи, на которых легко ошибиться

**`position: 0` в выгрузке Serpstat — это не первое место,** а «фразы нет в
первой сотне». Конвертер переводит такое в `null`. Если посчитать нули за
позиции, топ-3 на срезе 09.08 раздувается с 670 до 852, и вся сводка врёт.

**Частотность 0 у 941 фразы из 1335 — это факт, а не потеря данных.** Взвешенные
метрики (видимость) таким фразам просто не дают веса. Делить на ноль там негде:
если во всей выборке нет ни одной фразы с частотностью, показывается прочерк.

**Срез 05.08 неполный** — позиции есть только у 242 фраз. В манифесте он помечен
`partial`, за базу сравнения его брать нельзя.
